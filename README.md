## 1. Project Overview

This system lets universities register academic certificate PDF hashes on a blockchain smart contract. Employers and students can verify certificates without trusting any central authority.

**Key properties:**
- Certificate PDFs are hashed locally; only their SHA-256 hashes are stored on-chain
- Optionally, an issuer can explicitly save and retrieve PDFs in their own Google Drive
- Verification requires **no wallet** (read-only RPC)
- Tampering with the PDF produces a different hash → verification fails
- Revoked certificates are clearly flagged

## 8. Starting the Frontend

```bash
cd "BTA PBL/frontend"
npm run dev
```

Open your browser at: **http://localhost:3000**

### Optional — Connect Google Drive

Google Drive storage is opt-in. The PDF remains on the device unless the issuer explicitly saves it.
Only the SHA-256 hash is stored on-chain. Drive files are stored in the connected Google account's
`BTA PBL Certificates` folder and can be retrieved by that account; this app cannot access other
Drive files. Retrieved PDFs are hashed again and checked against their saved hash.

1. In [Google Cloud Console](https://console.cloud.google.com/), create/select a project and enable the **Google Drive API**.
2. Configure the OAuth consent screen. If the app is in Testing mode, add the Google account you'll use as a test user.
3. Create an OAuth client ID with application type **Web application**. Add these authorized JavaScript origins:
   - `http://localhost:3000`
   - `http://127.0.0.1:3000`
4. Copy the client ID (not a client secret) into `frontend/.env.local`:
   ```env
   VITE_GOOGLE_CLIENT_ID=your-oauth-web-client-id.apps.googleusercontent.com
   ```
   `frontend/.env.example` shows the expected format. Never put a client secret in frontend code or an environment variable beginning with `VITE_`.
5. Restart the Vite frontend. On the University Dashboard, connect the authorized issuer wallet and select **Connect Google Drive**, then approve access.
6. To store a selected PDF, choose **Save selected PDF to Google Drive**. Choose **Refresh saved PDFs** to list saved documents, then **Retrieve PDF** to load and re-hash one for issuance.

The app requests the `drive.file` permission, which grants access only to files created by this app. Disconnecting Drive clears the in-memory access token; manage or revoke the app's consent in your Google Account settings. Google Drive is optional and is not required to issue or verify a certificate.

## 9. Deploying the Frontend to GitHub Pages

GitHub Pages hosts only the static React frontend. It does not host the Hardhat blockchain or smart contract.
The locally configured Hardhat RPC (`127.0.0.1:8545`) is not reachable by visitors. Until a contract is
deployed to a public network and the settings below are configured, the hosted site displays that the
blockchain is not configured; local development remains unchanged.

1. Create a GitHub repository and push this project to its `main` branch.
2. In the repository, open **Settings → Pages** and choose **GitHub Actions** as the build and deployment source.
3. The included `.github/workflows/deploy-pages.yml` builds the frontend and publishes it on pushes to `main`.
4. To enable blockchain functionality on Sepolia:
   - In Alchemy, create a **Sepolia** app and copy its HTTPS Sepolia endpoint. Do not use an endpoint containing `eth-mainnet`.
   - Create a dedicated test wallet, fund it with Sepolia test ETH, and copy `blockchain/.env.example` to `blockchain/.env`. Fill in `ALCHEMY_SEPOLIA_URL` and `SEPOLIA_DEPLOYER_PRIVATE_KEY`.
   - From the `blockchain/` directory, run `npm run deploy:sepolia`. The deployer wallet becomes the contract administrator; authorize the university issuer through the admin dashboard.
   - Never use a wallet that holds real funds. The deployer key stays in the ignored local `.env` file and is not needed by GitHub Actions.
   - Add these **Actions variables** under **Settings → Secrets and variables → Actions → Variables**:
     - `VITE_CONTRACT_ADDRESS` — deployed contract address
     - `VITE_NETWORK_CHAIN_ID` — `11155111`
     - `VITE_NETWORK_NAME` — `Sepolia`
     - `VITE_RPC_URL` — browser-accessible HTTPS Sepolia JSON-RPC endpoint
5. To enable optional Google Drive storage, also add `VITE_GOOGLE_CLIENT_ID`. In the Google OAuth client settings, add the GitHub Pages origin (`https://<github-username>.github.io`) to **Authorized JavaScript origins**.

These values are embedded into the public frontend at build time. Do not put private keys, client secrets,
or privileged credentials in Actions variables or any `VITE_` variable. The Sepolia RPC URL (including
its API key) will be visible to site visitors. Restrict its allowed origin to
`https://muhammadubaidcse.github.io` and set provider quotas/rate limits. Rotate any API key already posted
in chat or committed to Git. The frontend source and public-chain transactions are not a secure substitute
for a production backend.

GitHub Pages does not serve the local development chain. Never use Hardhat's well-known test-account
private keys on a public network.

## 11. Demo Sequence

Use this sequence for classroom demonstration:

### Step 1 — Start infrastructure
```bash
# Terminal 1:
cd blockchain && npx hardhat node

# Terminal 2:
cd blockchain && npx hardhat run scripts/deploy.js --network localhost

# Terminal 3:
cd frontend && npm run dev
```

### Step 2 — Authorize the university
1. Open http://localhost:3000/admin
2. Connect MetaMask with Account #0 (Admin)
3. Paste Account #1 address into the issuer field
4. Click "Authorize Issuer" → confirm in MetaMask

### Step 3 — Issue a certificate
1. Open http://localhost:3000/university
2. Connect with Account #1 (University)  
3. Drag `demo/DEMO_CERTIFICATE.pdf` into the dropzone
4. Observe the SHA-256 hash displayed
5. Click "Register Certificate Hash On-Chain" → confirm in MetaMask
6. Transaction hash is displayed on confirmation

### Step 4 — Verify the original
1. Open http://localhost:3000/verify (no wallet needed)
2. Drag `demo/DEMO_CERTIFICATE.pdf` — result: **Valid ✓**
3. Note the issuer address and timestamp

### Step 5 — Verify the modified file (integrity check)
1. On the same Verify page, drag `demo/DEMO_CERTIFICATE_MODIFIED.pdf`
2. Result: **Not Registered ⚠** — different hash → integrity failure

### Step 6 — Attempt duplicate registration (rejected)
1. Return to University Dashboard
2. Try to register `demo/DEMO_CERTIFICATE.pdf` again
3. Transaction fails: "certificate already registered"

### Step 7 — Revoke the certificate
1. In University Dashboard, click "Revoke" on the issued certificate
2. Confirm the dialog → confirm in MetaMask

### Step 8 — Verify revoked status
1. Return to Verify page
2. Drag `demo/DEMO_CERTIFICATE.pdf`
3. Result: **Revoked ✗** — hash still exists but is withdrawn

### Step 9 — Unauthorized account demo
1. Connect with Account #2 in University Dashboard
2. Observe "Not Authorized" warning
3. Attempting to issue fails

### Step 10 — Records Search, Filtering & CSV Export
1. In University Dashboard, view the summary stats cards (Total, Valid, Revoked)
2. Use the search bar or status dropdown to filter certificates by hash or validity
3. Click "Export CSV" to download an official spreadsheet log of all issued certificates with timestamps, hashes, and block numbers
4. Use the row "Verify" link or "Copy Hash" button for quick audit access

### Step 11 — Proof Receipts & Printable Audit Certificate
1. On the Verify page for any verified certificate:
2. Click **"JSON Proof"** to download the machine-readable cryptographic verification receipt
3. Click **"Print Audit Statement"** to preview and print/save the official academic credential verification record
4. Click **"Shareable Link"** to copy a direct verification URL (`/verify?hash=...`)

## 12. Troubleshooting

### "Contract not deployed" banner
→ Run `npx hardhat run scripts/deploy.js --network localhost` with the node running.

### MetaMask shows wrong balance or nonce errors
→ The local chain was restarted. In MetaMask: Settings → Advanced → Reset Account.  
→ Re-deploy the contract after reset.

### "Cannot connect to RPC" error on Verify page
→ Make sure the Hardhat node is running: `npx hardhat node`

### Frontend doesn't reflect new deployment
→ The deploy script updates `src/config/contract.js` automatically.  
→ Vite's hot-reload should pick it up. If not, restart `npm run dev`.

### Port 8545 already in use
→ Kill the process: (Windows) `netstat -ano | findstr 8545` then `taskkill /PID <pid> /F`

### Transaction fails with "wrong network"
→ Switch MetaMask to the Hardhat Local network (Chain ID 31337).
